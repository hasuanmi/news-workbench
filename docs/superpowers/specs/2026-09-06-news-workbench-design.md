## 1. 产品与形态确认

- **形态：** 独立 Web 工作台，前后端一体（Next.js 16 + React 19 + TS 5 + Tailwind 4 + shadcn/ui），工作流内置在后端（API Routes + 长驻 cron 调度），不依赖外部扣子工作流平台。
- **使用范围：** 内部编辑辅助工具，不公网注册；V1 简单角色体系（admin / editor），账号由管理员开通（先做 seed 管理员 + 简单登录，SSO/邮箱验证留扩展）。
- **核心原则（用户明确强调）：**
  1. 配置驱动——媒体、分类、重要等级、字数阈值、线索类型、评报维度全部在配置表 / 后台管理，工作流只读配置执行；
  2. 确定性交给规则，模糊判断交给 AI；
  3. AI 结果结构化输出 + confidence，人工可审核可修改；
  4. V1 以"可修正"为核心，不追求无人值守。

| 模块 | 时间态 | 核心产出 | AI 参与 | 依赖抓取 |
|---|---|---|---|---|

## 3. 技术架构

```
浏览器 (Next.js App Router, shadcn/ui)
  │  SSE 流式（评报生成、线索识别过程）
  ▼
Next.js API Routes
  ├── 业务 API：日历/线索/评报/配置/审核 CRUD
  ├── AI 服务层：结构化输出（JSON mode）+ SSE 流式（豆包/DeepSeek）
  ├── 抓取适配层：media_source 适配器（website/epaper），健康状态机
  └── 调度层：node-cron 长驻
        WF01 动态节点(日) · WF03 抓取(日) · WF04 线索识别(日09:00发布)
        WF06 周报(周) · WF07-09 评报(每日，时间待电子报更新时间确认)
        │
        ▼
Supabase (Postgres)：10 张业务表 + 用户表 + 配置表
  └── pgvector：文章 embedding 向量粗聚（同题聚类）
```

- **数据库：** Supabase（平台集成），迁移用 SQL 脚本管理。
- **AI：** 平台 LLM 集成（豆包/DeepSeek），所有业务判断节点强制 JSON schema 输出；评报正文走 SSE 流式。
- **抓取：** 后端适配器模式，`crawl_method` 每源可配（rss/html/epaper/manual）；失败重试 + 连续失败计数 + 状态灯（🟢🟡🔴）写回 `media_source`。
- **定时：** node-cron 在长驻服务内执行；cron 时间点本身存配置表，可后台调整。
- **对象存储：** 导入的原始文件、评报导出件存对象存储。

## 4. 数据模型（在 PRD 10 表基础上的补充）

保留 PRD 全部字段，补充以下设计决策：

**4.1 `calendar_event`（新闻节点）**
- `event_type`：`fixed`（周年类，存 `original_date` 原始年份，每年由规则计算周年与当年日期）/ `dynamic`（当期事件，存 `event_date`）。
- 导入规则（基于真实数据验证可行）：
  - 名称含"N 周年"→ fixed，正则提取基准年份；无法提取基准年的 → 标 `needs_review`。
  - 含"待确认/待定"→ dynamic + `review_status=pending`（7 条：广交会×2、服贸会、进博会、珠海航展、开学日、诺奖）。
  - 2024 当期事件（选举、展会、赛事等）→ dynamic + `event_date=2024日期`。
  - 来源列："国内国际事项"→ national；"广东广州事项"→ guangdong/guangzhou（粒度先统一 guangdong，详情在备注，后台可改）；"其他关注事项"→ other。
  - `category_id`：导入时按关键词规则预分类（节日/党史/讲话/会议政策/战略/主题日/广东广州/展会活动 8 类），低置信标 `needs_review`，不硬猜。
  - 全部导入数据先过 AI/规则初判后**默认进待审核队列**，管理员确认后 `enabled=true`。

**4.2 `media`（媒体）+ `media_source`（数据源）**
- xlsx 直接映射：层级→`media_level`(central/provincial/city)，地区→`region`，官网→1 条 website 源；电子报列：是 URL 的→ epaper 源；是文字描述（"官网同源/XX客户端/XX数字报"）→ 建源记录但 `source_url=NULL`、`crawl_status=untested`，进 PoC 清单。
- `monitor_clue` / `monitor_review` 两个开关独立配置。
- **种子补录**（xlsx 缺失但 PRD 评报必需）：南方都市报、新快报、信息时报（官网公开可查，PoC 阶段核实 URL）。
- 评报默认 6 家（广州日报/南方日报/南方都市报/新快报/羊城晚报/信息时报）通过配置标记，不写死。

**4.3 `news_clue`（线索）补聚合键**
- 增加 `series_key`（media_id + 归一化 series_name 哈希）：同一栏目/系列多日抓到只更新一条记录（`first_found_at` 保留、追加 article 关联、刷新最后出现时间），避免列表刷屏。

**4.4 `daily_review` / `news_topic`**
- `daily_review` 增加 `sections`（jsonb：今日重点/同题观察/同行亮点/总体观察 四段）+ `version`（人工每次修改留版本，可回溯）。
- `news_topic.related_article_ids` 用数组；聚类结果带 confidence，人工可改簇。

**4.5 配置表（PRD 10.1 的"可配置内容"全部落表）**
- `calendar_category`、`media`、`media_source`、`clue_type`（新栏目/系列报道/专题/特色策划）、`review_dimension`（6 维度，含 prompt_instruction/priority/enabled）、`app_config`（键值：重点稿字数阈值 2000、置信度阈值 0.85/0.60、14 天窗口、cron 时间、评报媒体名单等）。
- **规则：工作流代码中禁止出现业务阈值常量，一律从 `app_config` / 配置表读取。**

**4.6 用户与日志**
- `user`（id/username/password_hash/role/admin、enabled）。
- `task_log` 按 PRD；增加 `ai_audit_log`（记录每次 AI 判断的输入摘要/结构化输出/置信度/人工最终判定），用于调 Prompt 与阈值评测。

## 5. 工作流映射（PRD WF01–WF09 → 实现）

| WF | 实现要点 | V1 范围 |
|---|---|---|
| WF01 动态节点发现 | web 搜索限定权威源（政府网/新华社/人民网/部委/省市官网）→ AI 抽取结构化候选 → 待审核 | M1 先支持人工录入 + 审核流；自动搜索 M4 后接 |
| WF02 日历生成 | 纯规则：读 enabled 节点 → 算 14 天窗口/周年/排序 | M1 ✅ |
| WF03 文章抓取 | 适配器 + 去重(content_hash) + 健康状态 + task_log | M2 PoC → M3 |
| WF04 线索识别 | 新文章 → AI JSON 判定（is_clue/type/series/topic/tags/summary/confidence）→ 阈值路由 | M3 |
| WF05 线索发布 | 09:00 取上轮审核通过线索 → 卡片列表 | M3 |
| WF06 周报 | 每周读 7 天线索 → AI 二次分析（新栏目/重点系列/集中主题/特色策划）→ SSE 可看生成过程 | M3 |
| WF07 重点稿 | 规则（字数/版面标记）+ AI 补充 | M4 |
| WF08 同题聚类 | embedding 向量粗聚 → AI 对候选簇 same_topic 确认 | M4 |
| WF09 评报 | 结构化卡片（不塞全文）+ 六维配置 → 四段生成 ≤1000 字 → 流式 → 人工可改进版本 | M4 |

**Token 策略（关键）：** 文章入库后先 AI 压缩成"结构化卡片"（主题/关键词/事件主体/角度/形式/200 字摘要），聚类与评报只用卡片 + 必要原文片段，避免全文爆上下文。

## 6. 页面结构

- **前台（editor 可见）：**
  - 首页：三模块聚合摘要（未来 7 天节点数 + 今日线索数 + 最新评报入口）
  - 新闻日历：周/14 天/月/指定日期切换，分类·地域·等级·固定动态筛选，关键词搜索，节点详情抽屉（名称/日期/周年/分类/地域/来源链接/备注）
  - 新闻线索：日期·媒体·类型·标签筛选，卡片（媒体/栏目名/类型徽章/AI 摘要/标签/原文链接/首次发现），周报页
  - 每日评报：日期选择，四段结构展示，同题簇对比卡片，原文链接，进入审核编辑
- **后台（admin）：**
  - 节点审核 / 线索审核 / 评报审核（三个待办队列，通过·修改·驳回·停用）
  - 节点 CRUD、分类管理、媒体管理（含两个监测开关）、数据源管理（PoC 状态灯 + 手动测试按钮）
  - 线索类型配置、评报维度配置（启停/说明/优先级/prompt）、全局参数配置（阈值/cron）
  - 运行日志（task_log）、AI 审核日志、账号管理

## 8. 里程碑（与 PRD Phase 对齐，含验收标准）

- **M0 工程地基**：Next.js 初始化 + Supabase 建表迁移 + shadcn 骨架 + 登录/角色 + xlsx/docx 导入脚本（131 媒体 / 410 节点入库，待审核状态）+ 配置种子（8 分类/4 线索类型/6 评报维度/阈值）。
  - 验收：媒体 131+3 条、节点 ~410 条可在后台看到并审核；配置页可改。
- **M1 新闻日历闭环**：14 天规则计算（含周年）、前台视图/筛选/搜索/详情、后台 CRUD/启停/分类调整、动态节点人工录入+审核流。
  - 验收：周年计算单测通过；固定/动态/待确认三类展示正确；改配置不改代码。
- **M2 数据源 PoC**：选 6–10 家（含评报 6 家）跑适配器，产出可用性表写入 media_source，后台可手动触发"测试抓取"。
  - 验收：每家有 🟢🟡🔴 状态与失败原因；🟢 的能稳定入 article。
- **M3 新闻线索**：WF03/04/05/06 全链路 + 卡片页 + 周报 + 审核流。
  - 验收：正/负样本识别准确率人工抽检；同系列不刷屏；周报可流式查看。
- **M4 每日评报**：WF07/08/09 + 六维比较 + 同行亮点 + 1000 字流式评报 + 人工修改留版本。
  - 验收：用人工评报 Golden Set 对比主题/聚类/亮点；可编辑保存。
- **M5 反馈调优**：日志驱动调阈值/Prompt。

## 9. 待确认 / 已知风险

1. **评报发布时间**：待确认各家电子报更新时间后定 cron（先默认每日 10:30，配置可调）。
2. **广州日报内部数据源**：用户后续向使用方确认；抓取层预留 adapter 切换，内部接口可用时替换公开抓取。
3. **电子报版面信号**（整版/跨版/头版）：多数网站列表页无此字段，WF07 规则降级为"字数 + AI 判断"，电子报适配器能解析版面时再启用。
4. **账号开通方式**：V1 管理员开号，后续接企业 SSO。
5. **xlsx 中 ~半数电子报为文字描述非 URL**：PoC 阶段逐一补 URL，不阻塞 M0/M1。
6. 抓取合规：仅抓公开可访问页面，遵守 robots 与频控（默认单源间隔 ≥10s）。
