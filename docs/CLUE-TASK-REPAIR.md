# 自动抓取与线索日志修复（2026-09-18）

保持三家PoC范围和原AI提示词；未执行结构migration、数据删除或批量重置processed。

## 修复

- Windows launcher使用隐藏且隔离的子进程运行Node，记录启动/退出码。原任务0xC000013A仅证明进程被中断，谁发出中断尚未证实；不把启动隔离描述为已确认全部根因。
- 锁改为检查worker PID是否存活，不再因死进程的锁等待90分钟。下一轮把未完成的旧run归档为interrupted，保留旧日志。
- runner启动即记录status、phase、PID、run_id；抓取和HTTP识别在开始前先写步骤，结束时保存结果，日志使用临时文件原子替换。一个来源异常继续其他来源，整体失败可追踪。
- Windows任务失败后5分钟补跑、最多2次。原时间不变：日历07:30、三家媒体抓取08:30，抓取阶段完成后识别。仍要求本机开机并登录。
- pipeline全部正常返回分支都记录task_log与本地run日志，包括空输入和结构/查询失败。保存时间条件、输入篇数/媒体数、逐文章调用结果、处理数量、错误及run_id。
- DeepSeek调用数从实际发起HTTP请求的回调计数，不把缺配置、数据库失败、空输入当作调用；每次仍一篇、正文前800字符。未改prompt或分类判断。
- /api/admin/leads/identify返回实际total/processed/executed/run_id/summary，修复原API仅返回栏目统计、前端拿不到本轮处理数的问题。
- 新闻线索页新增运行摘要：三家正式接入名称、最近抓取状态和时间、有效正文数、成功推送媒体数、最近24小时全媒体待识别数、最近一轮输入媒体/篇数及DeepSeek调用数，每15秒刷新。
- 空输入提示和空结果区明确显示“本轮未执行识别：待处理文章0篇”；不把无输入解释成模型判断没有新栏目。数量查询失败显示失败，不显示0。
