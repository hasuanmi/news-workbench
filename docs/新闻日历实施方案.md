## 2. 三个页面的结构

| 路由 | 页签 | 权限 | 内容 |
|---|---|---|---|

## 3. 历史日历上传解析流程

```
选择文件（docx / xlsx / csv）
   ↓
上传 → 存原始文件到 assets/history/，写 calendar_history_file（parse_status=uploaded）
   ↓
选择/识别年份（下拉可选 + AI 从文件名/内容识别，默认取识别值，可改）
   ↓
解析
   ├─ docx：parseDocxTables()（已有，复用）
   ├─ xlsx：XLSX.utils.sheet_to_json（已有 xlsx 依赖）
   └─ csv：按分隔符解析
   ↓
AI 补全/校正字段（DeepSeek v4-pro）
   输入：原始行文本
   输出：{ 节点名称, 日期或月份, date_status, 分类, 地区, 重要等级, 备注 }
   ↓
结构化预览（可编辑表格）
   | 日期 | 节点 | 分类 | 地区 | 重要等级 | date_status | 操作 |
   支持逐行修改 / 删除 / 新增
   ↓
用户确认保存
   ↓
写 calendar_history_node，更新 calendar_history_file（parse_status=confirmed, node_count）
```

要点：
- **上传后不直接入库**，必须走预览确认（方案要求）
- 年份**动态配置**，不写死
- 原始文件永久保留，换解析规则可重跑

## 4. 候选生成流程

### 入口一：从历史日历生成（历史节点迁移与年度候选生成）

```
点击【从历史日历生成候选】
   ↓
弹窗：参考年度（多选，来自 calendar.historical_years）+ 目标年度（默认次年）
   ↓
读取选中年度的 calendar_history_node
   ↓
规则分类（calendar-engine.ts 扩展）
   ├─ 固定日期节点（如 4月15日 全民国家安全教育日）
   ├─ 每年重复节点
   ├─ 周年纪念节点（用 anniversary_base_year）
   ├─ 年度会议 / 展会
   ├─ 固定月份但日期浮动（→ date_status=month_known）
   └─ 广东/广州持续关注节点
   ↓
复用 computeOccurrence(node, targetYear) 计算目标年度日期
   ↓
写入 calendar_candidate（source_type=historical_migration，source_detail="来自 20XX 年历史日历"）
   ↓
触发去重（§5）
```

> 对外表述：**「历史节点迁移与年度候选生成」**，不写"AI 学习新闻规律"。

### 入口二：AI 补充候选

```
点击【AI补充候选】→ 选目标年度
   ↓
组装 Prompt：
   - 目标年度
   - 已有候选摘要（避免重复）
   - 历史不采纳记录（负面样本，见 §6 反馈沉淀）
   ↓
DeepSeek v4-pro 生成新增节点 JSON
   ↓
写入 calendar_candidate（source_type=ai_supplement，带 ai_reason）
   ↓
触发去重
```

### 入口三：粘贴信息识别

```
点击【粘贴信息识别】→ 粘贴会议通知/政策/活动/公众号/新闻稿
   ↓
DeepSeek 抽取：
   { node_name, date 或 month, date_status, category, region, importance }
   ↓
结构化预览（可修改）
   ↓
确认 → calendar_candidate（source_type=pasted_text，raw_text 存全文）
   ↓
触发去重
```

**三条铁律**：三个入口的产物**一律进候选池**，绝不直接写 `calendar_event`。

## 5. 去重合并逻辑

### 第一层：规则匹配（快、免费）

比较维度：
1. **标准化名称**：去除届次数字（第138届）、括号内容、常见别称映射（广交会 ↔ 中国进出口商品交易会）
2. **年份相同**（target_year）
3. **日期接近**：都有确定日期时 ±7 天内；否则同月视为接近
4. **分类相同** 且 **地区相同**

命中 → 标记 `dedup_status=duplicate`，进入合并候选队列。

### 第二层：AI 语义判断（准、收费）

对规则层无法确定的（名称不同但疑似同事件），调 DeepSeek：

```json
{
  "same_event": true,
  "canonical_name": "中国进出口商品交易会（广交会）",
  "confidence": 0.94
}
```

- `confidence >= 0.85`（`calendar.dedup_ai_threshold`）→ 自动合并
- `< 0.85` → 标为「疑似重复」，交给人工在候选页手动合并

### 合并规则

- **不删除任何记录**
- 保留主候选，其余置 `dedup_status=merged` + `merged_into_id=主候选id`
- 主候选的 `merged_sources` 累积所有来源类型，如 `["historical_migration","ai_supplement","pasted_text"]`
- `canonical_name` 采用 AI 建议的规范名
- 多来源命中同一节点 → 视为高可信度，UI 上打「多源印证」标记

## 6. 人工审核流程

### 四种操作

| 操作 | 行为 |
|---|---|
| **确认加入日历** | 写入 `calendar_event`（review_status=confirmed, enabled=true），候选置 confirmed，记录 source_candidate_id |
| **修改后加入** | 先弹表单改 名称/日期/分类/重要等级/地区，再写入正式日历 |
| **合并** | 与已有候选或已有正式节点合并（走 §5 合并规则） |
| **不采纳** | **必须选择原因**，写 rejection_reason + reviewed_at + reviewed_by |

### 不采纳原因枚举（方案给定）

```
not_important        不属于重要新闻节点
one_off              一次性事件
no_continuity        不具备年度延续性
low_local_relevance  与广东/广州关联度低
duplicate            已有重复节点
unreliable           日期或来源不可靠
wrong_category       分类不合适
insufficient         重要性不足
expired              已过期/已失效
other                其他
```

### 反馈沉淀（方案第九节）

- 所有审核记录（采纳 + 不采纳 + 原因）完整保存
- **AI 补充候选时，把历史不采纳记录作为负面样本注入 Prompt**
- 例：业务方多次标记「普通商业节日 → 不采纳」「广州重大展会 → 保留」「国家级重要纪念日 → 高优先级」
- 效果：专家教一次，系统后续减少同类误判，而不是每年从零判断

## 8. 已拍板的决策

1. **AI 补充候选不受"参考年度"限制** —— 只针对目标年度生成，不参考历史日历（它的价值正是补历史里没有的新增节点）。
2. **候选节点仅管理员可见可操作** —— 编辑角色不放开；`/calendar/candidates` 与 `/calendar/history` 均 `requireAdmin`。

## 9. 实施顺序建议

1. 数据库 schema + 迁移脚本（可先跑，不影响现有功能）
2. 历史日历上传解析（有数据才好生成候选）
3. 候选生成入口一：历史迁移（纯规则，最可控）
4. 去重合并（规则层先上，AI 层后上）
5. 人工审核流程
6. 候选生成入口二、三（AI 补充、粘贴识别）
7. 日历视图增强（月/周视图、待定区）

每步完成都可独立验证，不会长时间阻塞。
